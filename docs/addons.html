Add-ons

Your own tab.
Two files.

An add-on is a small web page (HTML + JavaScript) that VellFire shows as an extra tab. It runs sealed off, reads the data you'd expect, and can't touch anything that matters.

Read-only

It can read quotes, bars, the Montage stock and your watchlist. Nothing else.

Sandboxed

No orders, no settings, no keys, no account, no journal. Calls that try are refused by VellFire and blocked by the browser.

Yours

Add-ons live in your data folder, never in the program folder, so they stay yours through every update.

Where they live

Settings › Add-ons › Show add-ons folder opens the folder (and creates it the first time). Each add-on is one sub-folder, named the same as its manifest's name:

%LOCALAPPDATA%\VellFireAi\plugins\
    myaddon\
        manifest.json
        index.html
        (any other files: .js .css .png .svg .json ...)

Portable copy: the plugins folder sits inside "VellFire Data" next to the exe.

manifest.json

{
  "name": "example",
  "title": "% from open",
  "icon": "%",
  "entry": "index.html",
  "version": "1",
  "author": "VellFire example"
}
  • name: 1-32 characters, only a-z 0-9 _ -, and the same as the folder name.
  • title: what the tab is called (up to 40 characters). entry: the page to open (default index.html).
  • version, author, icon (1-4 characters, an emoji works): optional.
  • lock (optional): "lock": "A Name" makes it load only when VellFire's licence name matches.
  • hosts (optional): "hosts": ["api.example.com"] lists internet sites it wants to fetch from (https only, at most 5). Internet is off until you click Approve in Settings › Add-ons.

index.html: the bridge

Put <script src="_vf.js"></script> in your page (VellFire supplies _vf.js). It gives you vf, the only way to get data:

<!doctype html>
<html><head><meta charset="utf-8"><title>% from open</title></head>
<body>
<script src="_vf.js"></script>
<h2 id="sym">-</h2><div id="out">waiting...</div>
<script>
async function show(sym) {
  document.getElementById("sym").textContent = sym || "-";
  if (!sym) return;
  const q = await vf.quote(sym);            // {sym, last, chg, delayed}
  const b = await vf.bars(sym, "5m");       // {bars: [{time, open, high, low, close, volume}], source}
  const open = b.bars.length ? b.bars[0].open : null;
  document.getElementById("out").textContent =
    `last ${q.last}  ·  ${open ? ((q.last / open - 1) * 100).toFixed(2) + "% from open" : ""}`;
}
vf.onSymbolChange(show);                    // follows the Montage on the Trade screen
vf.montageSymbol().then(show);
vf.watchlist().then(list => console.log("watchlist", list));
</script>
</body></html>

Every call returns a Promise; a refused call rejects with an Error that says why. Timeframes: 1m 5m 15m 30m 1h D W. Limits: 20 calls a second, bars 30 a minute. An add-on never moves the Montage.

Try it

  1. Make a folder in the add-ons folder, put a manifest.json and an index.html in it (the example above is enough).
  2. Press F5 in VellFire. The tab appears under More ▾ › Add-ons (and in Settings › Add-ons, with on / off).
  3. Edit your files, press F5 on the add-on's tab to see the change.
  4. If it won't load, Settings › Add-ons says why (for example "name must match its folder name").

The rules

  • Read-only. No orders, no settings, no keys, no account, no journal.
  • No internet unless you approve its hosts. No pop-ups, alert boxes, forms, downloads, camera or microphone. No localStorage.
  • Files are served only from the add-on's own folder; .. paths are refused.
  • Remove = Settings › Add-ons › Remove: the folder is moved to plugins\_removed, nothing is deleted.
  • VellFire is software for education and research. An add-on is not financial advice either.
